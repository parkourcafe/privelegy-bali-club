## Правила исполнения — обязательные

1. Один фикс — один коммит, в сообщении ссылка на находку (номер из этого ТЗ).
2. **Каждый кодовый фикс несёт регрессионный тест, который поймал бы эту же
   ошибку.** Фикс без теста не принимается — все сегодняшние находки дожили до
   аудита именно потому, что теста не было.
3. Перед пушем — гейты §18: lint, typecheck, build, npm test.
4. Данные — только через скиллы: `otherbali-supabase-write` (dry-run
   обязателен), `otherbali-venue-record-standard` для редакционных полей.
5. Блок E не трогать без решения владельца — это не очередность, а граница.
6. Не смешивать волны в одном PR: волна 1 (код) отдельно, миграция отдельно,
   редакционные партии отдельно.
7. После мержа проставить статус в этом файле тем же PR.

### F5 · Миграция 0066: revoke дефолтных грантов `anon` [P2] — статус: ПРИМЕНЕНО К ПРОДУ владельцем 09.08, проверено запросом

~20 таблиц несут дефолтные гранты вплоть до DELETE/TRUNCATE (`guest_refs`,
`events`, `consent_log`, `redemption_events`, `venue_submissions`…). Политик
записи для `anon` нет — не эксплуатируется, но новые миграции (0031+) уже
снимают гранты у своих таблиц; долг только на старых.

Объём: миграция `0066_revoke_default_anon_grants.sql` по образцу 0031:
идемпотентно, `revoke all … from public, anon, authenticated`, затем
`grant select` только таблицам с публичной SELECT-политикой (список — в
аудите). Перед написанием — `list_migrations` по проду: прод может опережать
репозиторий. Применение к проду — отдельный шаг владельца, записать в handoff.
Приёмка: аудиторский запрос грантов (в отчёте) возвращает пусто по
перечисленным таблицам; публичные страницы и smoke-тесты живы.

Итог исполнения: миграция написана и проверена dry-run'ом на живой продовой
схеме внутри транзакции с гарантированным откатом: после применения опасных
грантов остаётся 0, SELECT сохранён на всех 11 читаемых таблицах, откат
подтверждён (21 DELETE-грант на месте после прогона). Политик записи для
anon/authenticated не существует ни одной (проверено по pg_policies), поэтому
revoke ничего не ломает. Применено к проду владельцем 09.08 через SQL Editor; проверка
после применения: write-грантов у anon/authenticated — 0 во всей схеме, SELECT
на 16 закрытых таблицах — 0, SELECT сохранён на 11 из 11 читаемых, и роль anon
читает ровно 1214 опубликованных карточек через RLS-политику.
