# ТЗ: сбор признаков заведений через Google Places API

**Дата:** 2026-08-04 · **Кому:** отдельный агент / скрипт
**Задача:** заполнить `practical_tags`, `opening_hours`, координаты для
опубликованных заведений. Сейчас `practical_tags` есть у 28 из 1246 (2%),
часы — у 184, координаты — у 621.

---

## 1. Граница, которую нельзя переходить

**Берём:** структурированные поля объекта (Place Details) — это факты
о заведении, которые Google хранит как атрибуты.

**Не берём:** `reviews`, `rating`, `userRatingCount` и любые выводы из
текста отзывов. Гардрейл проекта №2 запрещает переносить в публичный
контент прозу отзывов, рейтинги и производные от них утверждения; условия
Google отдельно запрещают скрейпинг отзывов. Поля `rating`/`reviews`
**не запрашивать вообще** — так их физически не окажется в выгрузке.

Читать отзывы глазами, чтобы понять, какие признаки вообще важны на
Бали, — можно: это исследование. Публиковать «есть розетки», потому что
так написано в отзыве, — нельзя.

## 2. Какие поля запрашивать

`GET https://places.googleapis.com/v1/places/{PLACE_ID}`
заголовок `X-Goog-FieldMask` — строго этот список:

```
id,displayName,formattedAddress,location,businessStatus,
regularOpeningHours,priceLevel,websiteUri,
parkingOptions,paymentOptions,accessibilityOptions,
goodForChildren,goodForGroups,outdoorSeating,restroom,
servesVegetarianFood,allowsDogs,liveMusic,reservable,
delivery,takeout,dineIn
```

`rating`, `reviews`, `userRatingCount` в маску **не включать**.

## 3. Как поля ложатся на наш словарь

| Поле Places | Наш `practical_tags` |
|---|---|
| `parkingOptions` (любой из вариантов true) | `parking` |
| `goodForChildren` | `kid-friendly` |
| `goodForGroups` | `big-groups` |
| `reservable` = false | `walk-in-friendly` |
| `reservable` = true | `reservation-helpful` |
| `paymentOptions.acceptsCreditCards` | `card-ok` *(новый)* |
| `servesVegetarianFood` | `veg-friendly` *(новый)* |
| `outdoorSeating` = false | подсказка к `rain-proof` — **не проставлять автоматически**, см. §5 |
| `allowsDogs` | `dog-friendly` *(новый)* |

Отдельными колонками, не тегами:
`location` → `latitude`/`longitude` · `regularOpeningHours` →
`opening_hours` (синтаксис schema.org, см. ТЗ по часам) ·
`businessStatus` → сигнал о закрытии заведения.

**Чего Places не даёт вовсе:** розетки у столов, вайфай, кондиционер.
Это самые ценные для нас признаки (раздел «поработать»), и собрать их
можно только от владельца или визитом. На API не рассчитывать.

## 4. Что делать с заведениями без `place_id`

`google_place_id` есть у 557 из 1246. У остальных 689 его нет, и
координат тоже нет.

Для них — Text Search по `name + address`, но с жёстким правилом:
**сопоставление принимается, только если совпадает и название, и адрес**
(один и тот же город/улица). При любом сомнении — пропустить и записать
в отчёт. Подставить чужое заведение хуже, чем не подставить никакого:
неверный адрес на карточке — это отправленный не туда человек.

Найденный `place_id` сразу писать в `google_place_id` — его хранить
можно бессрочно, в отличие от остальных полей (§6).

## 5. Правила заполнения

1. **Поле отсутствует в ответе ≠ признак отсутствует.** Google часто
   просто не знает. Тег ставим только на явное `true`; на `false` и на
   отсутствие поля — не ставим ничего.
2. **`rain-proof` автоматически не ставить.** Это наша оценка (есть ли
   крыша, работает ли место в ливень), а не поле Google. Существующие
   27 проставлены редакцией — их не трогать.
3. **Существующие значения не перезаписывать.** Если у заведения уже
   есть `practical_tags` или `opening_hours`, заполненные редакцией или
   владельцем, — они старше и точнее. Дописывать только пустое.
4. **`businessStatus`** ≠ `OPERATIONAL` — не удалять заведение
   автоматически, а вынести в отчёт для проверки человеком.

## 6. Хранение: важное ограничение

Условия Google разрешают бессрочно хранить только `place_id`. Остальные
поля полагается обновлять, а не считать вечными. Практический вывод:

- **координаты** — стабильны, обновление раз в год достаточно;
- **часы и атрибуты** — помечать датой сбора и перепроверять;
  часы меняются постоянно, и устаревшие часы на карточке хуже их
  отсутствия.

Поэтому каждая запись должна нести `verification_source = 'google_places'`
и `verified_at` — по ним всегда видно, что откуда и когда.

## 7. Формат результата

CSV: `slug,google_place_id,latitude,longitude,opening_hours,practical_tags,business_status,checked_at,note`

`practical_tags` — через точку с запятой: `parking;kid-friendly;card-ok`.
Пустое поле — нормально.

## 8. Стоимость и объём

Place Details с расширенной маской — порядка $0.02 за вызов.
557 заведений с `place_id` ≈ **$11**. Text Search для остальных 689 —
дороже за счёт двух вызовов на объект, ориентировочно **$25–35**.
Итого до **$50** на весь каталог. Это дешевле любого ручного прохода.

## 9. Отчёт по итогам

Кроме CSV — короткая сводка: сколько сопоставлено уверенно, сколько
пропущено из-за несовпадения адреса, у скольких `businessStatus` не
`OPERATIONAL`, сколько заведений так и осталось без координат и часов.
Пропуски важнее находок: по ним видно, где нужен человек.
