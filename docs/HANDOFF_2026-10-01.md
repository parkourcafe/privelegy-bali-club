# Other Bali web release candidate — source fixes after the full audit

Base: `a15f9f1` on `release/website-candidate-20260928`, draft PR #314. This
handoff covers repository changes only. No production database migration,
merge, production deployment, browser acceptance, or second manual CI run is
included.

## Changes

- Primary venue read errors now escape `unstable_cache`; a successful missing
  slug remains `null`. Optional perk failure leaves a valid venue available.
  The detail cache key is versioned to avoid previously cached false 404s.
- Expanded menu items display every verified allergen. PlaceCard's stretched
  link now has a card-local positioning context. Exact pointer bounds still
  need browser hit testing.
- Public photo policy accepts only canonical or current trusted preview
  `/api/venue-photo/<UUID>` delivery URLs, after the existing publication and
  photo-status gates. The delivery endpoint still checks approval and consent.
- My Bali distinguishes an empty trip, missing legacy RPC, and read failure.
  The page shows a retry state rather than claiming saved places were lost.
- Partner invitation replay no longer rewrites a revoked, suspended, or
  demoted membership to active owner. New claims use inserts rather than
  upserts. A hosted concurrency and revocation check is still required.
- Migration `0067_submission_intake_ownership.sql` changes public intake to
  insert-only on the name/district collision. Duplicates do not return the
  existing submission ID, contacts, reference, or a media capability. The
  versioned RPC makes the new web route fail closed before migration apply.
  Apply only after reconciling the production migration ledger; no SQL was run
  against a database during this task.
- The Wave 2 boundary test now checks the current Ubud decision rail and
  current partner copy instead of the expired September 21 pilot claim.
